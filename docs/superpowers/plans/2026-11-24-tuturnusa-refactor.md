## Aturan eksekusi dan batas file

Claude menyiapkan tiga worktree dari **commit dasar yang sama** untuk setiap gelombang, membagikan kontrak halaman dan data di bawah, lalu menggabungkan hasil setelah setiap worktree lulus `bash scripts/ci.sh`. **Gelombang berikutnya baru dimulai setelah Claude merge semua tugas gelombang sebelumnya dan GitHub Actions CI hijau.** Setiap agent hanya menyentuh daftar file miliknya; perubahan yang ternyata membutuhkan file milik agent lain dicatat untuk gelombang berikutnya. Perintah `git diff --name-only` harus dicocokkan dengan daftar kepemilikan sebelum merge. Tidak ada commit dari Codex pada tahap penulisan rencana ini.

Urutan dibuat agar tiap cabang dapat hijau sendiri. W0 membetulkan tes yang bergantung pada berkas lokal. W1 menambah fondasi backend, UI, dan materi secara paralel tanpa mengubah rute produk yang aktif. W2 mengaktifkan tiga fitur dan menghapus PHP/rute/tes lama dengan UI serta materi W1 sudah tersedia. W3 membersihkan view dan JS yang tidak lagi dirujuk. W4, gelombang **terakhir sebelum QA manual**, memasang E2E dan job CI. W1 adalah pekerjaan paralel untuk ketiga agent; W0/W2/W3/W4 sengaja hanya mempunyai satu pemilik bila perubahan harus berurutan.

Sebelum mulai setiap tugas: baca file yang akan disentuh, cari semua pemakai dan penguji (`rg -n` untuk string Blade/JS/config dan pemanggil dinamis), lalu jalankan tes terkait. Graph MCP diprioritaskan sesuai `AGENTS.md` bila tersedia; pada sesi perencanaan ini tool graph tidak tersedia, sehingga implementer harus memakai pemeriksaan source dan mengungkap gap tersebut. Untuk bug pada fungsi bersama, periksa seluruh pemanggil sebelum edit. Jangan menghapus migrasi/tabel historis, `User`, `auth.php` config bawaan, layanan AI Ngobrol, layanan kamus Ucapan, `WeekTopic`, HSK, atau job analisis. `files (1)/` dan PDF sumber tetap.

**Kontrak integrasi W1:** Codex membuat katalog Buku Saku dan controller yang mengirim `books`, `book`, `chapters`, `chapter`, `previous`, `next`, `audioUrl`, dan `durationSeconds` ke tiga view `buku-saku/{index,book,chapter}.blade.php` milik Cursor; data hanya berasal dari slug katalog. Antigravity menghasilkan Markdown `00`, `01`–`15` / `01`–`12`, `99` bila ada, MP3 `<slug>/<NN>.mp3`, dan `public/audio/buku-saku/manifest.json` sesuai format S1. Backend W1 boleh diuji dengan fixture kecil di `tests/Fixtures/buku-saku/`, tetapi belum mendaftarkan rute Buku Saku. Cursor boleh menguji view melalui `view()` dengan data sintetis; template aktif lama tidak dihapus sebelum W2. Ketiganya tidak saling menunggu edit file.
